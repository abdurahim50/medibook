# NIST SP 800-53 control mapping

How MediBook's controls map to [NIST SP 800-53 Rev. 5](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final), with the evidence for each. This is a self-assessment of a portfolio system with synthetic data, not an authorization. It covers the application, the delivery pipeline and the AWS dev environment.

**Status:** **Implemented** means the control is in place and evidenced. **Partial** means in place with a stated gap. **Planned** means not yet in place.

## Main gaps before real patient data

1. **SC-8:** HTTPS with an ACM certificate; no plain HTTP listener.
2. **CP-9 and CP-10:** RDS PostgreSQL (Multi-AZ, encrypted, automated backups) and a tested restore.
3. **SI-7:** signature verification enforced at deploy time, not by an operator.
4. **AU-9 and AU-11:** longer retention and logs in a separate, write-protected account.
5. **IA-2(1) and AC-2:** MFA and account lifecycle management, including staff roles.
